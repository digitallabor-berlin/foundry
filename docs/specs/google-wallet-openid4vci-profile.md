Documents the current Google Wallet OpenID4VCI implementation that either differs from the regular specification or has made a specific choice when multiple options are offered by the spec

# VCI Issuance

| DPC Type | SD-JWT, VCT \= com.emvco.dpc.card |
| :---- | :---- |
| **Issuer Onboarding** | The current Google Wallet infrastructure requires an extra onboarding step. It needs to hard code your issuer metadata on its backend. Therefore, please share with Google Wallet your credential issuer metadata once it’s ready to kick off the onboarding step. |
| **Pre-Auth-Code Support** | Google Wallet for now only supports pre-auth code flow and does not support auth code flow, which is on the roadmap. |
| **Wallet (Client) Attestation** | [Challenge endpoint](https://datatracker.ietf.org/doc/html/draft-ietf-oauth-attestation-based-client-auth-10#section-6.1) is supported and required for wallet attestation The signing key for both the client attestation and client attestation PoP JWT are P-256 keys.  wallet\_name \== "Google Wallet" Root keys are the ones found here: [https://developer.android.com/privacy-and-security/security-key-attestation\#root\_certificate](https://developer.android.com/privacy-and-security/security-key-attestation#root_certificate) |
| **Token Endpoint** | DPoP is supported and required. DPoP Nonce is expected to be returned from the [Challenge endpoint](https://datatracker.ietf.org/doc/html/draft-ietf-oauth-attestation-based-client-auth-10#section-6.1) header.  Note: this is not standardized. Meanwhile, there's an active effort to standardize this way of retrieving the DPoP nonce, similar to how [it’s already been standardized](https://openid.github.io/OpenID4VCI/openid-4-verifiable-credential-issuance-1_1-wg-draft.html#section-8.2-4) to retrieve the Credential endpoint DPoP nonce from the c\_nonce endpoint. |
| **Key Attestation** | Google Wallet supports key attestation using the \`android\_keystore\_attestation\` extension point. This is the recommended way to perform key attestation on an Android device. It provides a hardware key attestation directly signed by the Android keystore. See [documentation here](https://developer.android.com/identity/digital-credentials/credential-issuer/keystore-attestation) |
| **Credential Endpoint** | DPoP, credential\_request\_encryption, and credential\_response\_encryption is supported and required.  DPoP Nonce is expected to be returned from [the c\_nonce endpoint](https://openid.github.io/OpenID4VCI/openid-4-verifiable-credential-issuance-1_1-wg-draft.html#section-8.2-4). |

# Examples

#### Challenge response

```
HTTP/1.1 200 OK
Host: as.example.com
Content-Type: application/json
Cache-Control: no-store
DPoP-nonce: eyJ7S_zG.eyJH0-Z.HX4w-7v

{
  "attestation_challenge": "AYjcyMzY3ZDhiNmJkNTZ"
}
```

#### Nonce response

```
HTTP/1.1 200 OK
Content-Type: application/json
Cache-Control: no-store
DPoP-Nonce: eyJ7S_zG.eyJH0-Z.HX4w-7v

{
  "c_nonce": "wKI4LT17ac15ES9bw8ac4"
}
```
